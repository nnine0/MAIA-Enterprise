### Project Overview
This project, referred to as "MAIA" (Multi-Agent Intelligent Assistant) or "MAIA Council Controller," is an AI-powered system designed for domain-specific query handling, retrieval-augmented generation (RAG), and continuous learning. It leverages a base large language model (LLM) fine-tuned with LoRA adapters for specialized "experts" across sectors (e.g., real estate, manufacturing, healthcare). The system integrates OCR for image processing, asynchronous task queuing, and a vector database for context retrieval. It appears to be built for enterprise or specialized applications, such as GDP valuation or expert consultation, with a focus on accuracy, security, and adaptability.

The project uses a microservices architecture deployed via Docker Compose, emphasizing GPU acceleration for inference and training. Key themes include "The Council" (expert adapters), "The AMR" (query routing), and "PVI Airlock" (response auditing).

### Purpose
- **Core Functionality**: Handle user queries by routing them to domain-specific experts (via LoRA adapters), retrieving relevant context from a vector database (Qdrant), generating responses using an LLM (Nanbeige/Nanbeige4-3B-Thinking-2511 via LoRAX), and auditing outputs for consistency.
- **RAG Integration**: Implements hybrid retrieval combining vector search, BM25 keyword search, and cross-encoder reranking for SOPs or documents.
- **Image Support**: Processes uploaded images via OCR (using PaddleOCR) and analyzes extracted text asynchronously via Celery.
- **Continuous Evolution**: Logs positive user feedback ("thumbs up"), triggers retraining, evaluates adapters, and rolls back if needed.
- **Training and Data Augmentation**: Scripts for generating synthetic training data via GPT-4o, fine-tuning LoRA adapters on augmented datasets, and processing gold-standard datasets (e.g., GDPval).
- **Security and Reliability**: Includes prompt injection detection via LLM-Guard, API key authentication, circuit breakers, and versioned adapter rollbacks.

The system seems tailored for tasks like expert advice, document analysis, or valuation in sectors mapped to GDP categories, with a philosophical or structured approach (e.g., "Deen al-Qayyim" framework for law).

### Components
The project is organized into Dockerized services and utility scripts. Here's a breakdown:

1. **Services (via docker-compose.yml)**:
    - **lorax**: Inference server using LoRAX for the base LLM (Nanbeige/Nanbeige4-3B-Thinking-2511) with LoRA adapters. Runs on GPU, serves the model at port 8080.
    - **vector-db (Qdrant)**: Vector database for storing and searching embeddings of documents/SOPs. Port 6333.
    - **redis**: Task queue backend for Celery. Port 6379.
    - **maia-app**: Main FastAPI controller (built from `./app`). Handles queries, semantic routing to experts, hybrid RAG, response auditing, and orchestration. Depends on other services. Port 8000. Includes GPU reservations.
    - **ocr**: OCR service (built from `./ocr`) using PaddleOCR for text extraction from images. Port 5000. GPU-enabled.
    - **trainer**: Training worker (built from `./app` with `Dockerfile.trainer`). Polls for update triggers and runs continuous learning via `train_update.py`. Shares volumes for adapters and logs.
    - **embeddings**: Embedding service (built from `./embeddings`) for generating query vectors and reranking. Port 6000.

2. **Application Code**:
    - **app/main.py**: FastAPI app with endpoints for text queries (`/query`), image queries (`/query_image`), task status (`/task/{task_id}`), adapter rollback (`/rollback_adapter`), training triggers (`/train_update`), and thumbs up logging (`/thumbs_up`). Implements semantic expert routing ("The AMR"), hybrid RAG (vector + BM25 + reranking), response generation with adapters, auditing, and sanitization.
    - **app/tasks.py**: Celery tasks for async OCR processing and MAIA analysis of extracted text.
    - **app/celery_app.py**: Celery configuration for task queuing with Redis.
    - **app/wait_for_trigger.py**: Polls for training triggers (via file or endpoint) and executes updates.
    - **ocr/main.py**: FastAPI app for OCR inference on uploaded images using PaddleOCR.
    - **embeddings/main.py**: FastAPI app for generating embeddings and reranking documents.

3. **Training and Data Scripts** (Root Directory):
    - **augment_gdpval.py**: Uses OpenAI GPT-4o to generate synthetic training data by augmenting gold-standard GDPval tasks per sector, saving sector-specific JSON files.
    - **council_inference.py**: Demonstrates loading the base model and LoRA adapters for inference across topics (law, math, puzzle, bio), with hot-swappable adapters.
    - **process_gdpval.py**: Processes gold GDPval datasets to synthesize chain-of-thought (CoT) reasoning using GPT-4o, formatting for training.
    - **train_expert.py**: Fine-tunes LoRA adapters on datasets (e.g., GSM8K for math, custom JSON for sectors), with oversampling of expert data and configurable parameters.
    - **train_update.py**: Orchestrates continuous learning: pulls thumbs-up logs from Qdrant, updates training data, retrains adapters with versioning, evaluates via LLM judge, rolls back if failed, and refreshes LoRAX.

4. **Configuration and Data**:
    - Volumes: `./adapters` (LoRA adapters), `./qdrant_data` (vector DB), `./data_logs` (training logs and triggers).
    - Metadata: `adapter_metadata.json` tracks adapter versions (timestamped) for rollbacks.
    - Networks: Custom bridge network (`maia-net`) for inter-service communication.
    - Experts: Mapped to GDP sectors (real_estate_leasing, manufacturing, professional_services, government, health_care, finance_insurance, retail_trade, wholesale_trade, information, general, trivium).

### Overall Structure
- **Architecture**: Event-driven microservices with async processing (Celery). Layered design: Inference (LoRAX), Memory (Qdrant + Embeddings), Queue (Redis), Controller (FastAPI), Senses (OCR), Evolution (Trainer).
- **Data Flow**: Query → Semantic Routing ("The AMR") → Hybrid RAG (Vector + BM25 + Rerank) → Generate Response with Adapter → Audit & Sanitize → Return. Images: Upload → OCR (Async) → Analyze.
- **Training Flow**: Gold Data → Augment/Synthesize (GPT-4o) → Fine-Tune Adapters (LoRA) → Evaluate (LLM Judge) → Deploy/Refresh LoRAX.
- **File Structure**: Clean separation (app/, ocr/, embeddings/, root scripts). Modular and scalable with Docker.

### Notable Features
- **Expert Specialization**: LoRA adapters for GDP sectors (e.g., finance_insurance, health_care), enabling domain-specific responses without full model retraining. Hot-swappable adapters.
- **Hybrid RAG**: Fully implemented with vector search, BM25 keyword matching, and cross-encoder reranking; context summarization if too long.
- **Security**: LLM-Guard for prompt injection detection, API keys, response sanitization (removes thinking tags), and circuit breakers.
- **Continuous Learning**: Thumbs-up logging to Qdrant, triggered retraining with versioning, LLM-based evaluation, and rollback mechanisms.
- **GPU Optimization**: 4-bit quantized models, LoRA fine-tuning, and GPU reservations across inference, OCR, and embeddings services.
- **Philosophical/Thematic Elements**: References to "The Council," "The AMR," "PVI Airlock" (auditing), "Deen al-Qayyim," suggesting a structured, ethical, and council-based AI approach.
- **Extensibility**: Easy to add sectors or datasets; supports local JSON, Hugging Face datasets, and configurable adapter training.

### Issues and Areas for Improvement
- **Incomplete Implementations**: Golden set loading for evaluation is placeholder (hardcoded empty). Some async/sync mixing in Celery tasks may cause issues.
- **Hardcoding**: Model ID, URLs, and sectors are hardcoded; could be config-driven. Adapter names and datasets in `train_expert.py` require manual editing.
- **Error Handling**: Limited error recovery in training loops; subprocess calls may fail silently. No retries for LoRAX refreshes.
- **Scalability**: Single-GPU per service; no horizontal scaling. Training is sequential per adapter; no parallel retraining.
- **Dependencies**: Relies on external APIs (OpenAI) for data gen; no offline fallbacks. PaddleOCR accuracy depends on image quality.
- **Security Gaps**: API keys in env vars; no rate limiting or advanced auth. Vector DB and logs may expose sensitive data if not secured.
- **Testing**: No visible unit/integration tests; relies on manual validation and LLM evaluation.
- **Documentation**: No README; code comments are sparse. Assumes deep familiarity with components like LoRAX and Qdrant.

This is a sophisticated, production-ready AI system for specialized querying and learning, but it requires careful setup (e.g., data, GPUs) and refinement for robustness. If you need help with specific tasks like adding features or debugging, provide more details!
